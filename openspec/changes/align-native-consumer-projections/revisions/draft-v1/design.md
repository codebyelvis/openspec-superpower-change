## Actual Entries and Transitive Consumers

The original seven names imply eight configurations: default Codex, account A,
claudex, claudeg, Cursor, Grok, Pi and agy. This slice's affected consumers are
the first six; Pi/agy bytes and portable records remain unchanged assertions.
Default Codex binds both its AGENTS and model instructions, while account A
does not bind the latter. The two Claude launchers use one rule file but require
distinct actual session identities. Cursor IDE and CLI are separate evidence
scopes. Grok may consume Claude and Cursor changes as compatibility inputs.

Before mutation, bind each affected native entry's actual launcher/config root,
native rule discovery, skill/dependency paths and event mechanism. Current
catalog or inspect metadata is discovery evidence, not native body loading.
Unsupported or unobservable loading must remain pending and block any claim
requiring it. Do not inject candidate content through project AGENTS and call
the resulting classifier native global-rule acceptance.

## Preparation, Apply and Recovery

After specific approval, prepare the executable implementation Plan and
bounded private commands/receipts for this change. The proposed backup root is
`/Users/elvis/Library/Caches/native-agent-adaptation/project-native-r2-20261010/`,
mode 0700, with six mode-0600 preimages and separately bound original modes.
It is outside skill discovery. Collision or drift stops preparation; a new
root requires refreshed binding, not adoption of an existing directory.

Before Preflight, supply actual commands, command hashes, native source/event
auditors and isolated failure injections. Recovery must restore the exact
bound preimage/mode or stop without overwriting concurrent drift. Test failed
candidate checks, preimage changes, linked paths, later-write stopping, receipt
freshness, mode restoration and publisher conflict classification. These tests
must use private fixtures, not live native writes or auth copies.

Independent Preflight reviews the complete executable package. With PASS,
process files 01–06 in the candidate manifest order. Bind source and complete
file prestate again before backup and before replacement; verify candidate,
outside bytes, modes and durable receipt afterward. Stop later writes on failure.
No six-file atomic guarantee or automatic cascading rollback is asserted.
Any conflicting replacement inode or content leaves recovery blocked for the
owner rather than overwriting another writer.

Read-only model acceptance may still invoke hook/session side effects; record
the allowed state and qualified command controls before a launch. Do not use
tools-disabled, plan mode or correct answers as a substitute for event auditing
or mutation checks. No publisher call or report publication is authorized by
this slice; coexistence uses pure-function/fixture probes and classified native
responses. Raw events stay private and temporary; durable evidence contains
only sanitized paths/hashes/enums/counts and limitations.

## Verification and Completion

Required offline checks: managed parity, exact-edit reversibility, preserved
bytes/modes, dependency/publisher/excluded-target invariance, failure-injection
recovery and A–F/P1–P3 expectations from the r2 plan. Required native acceptance
covers both Codex roots, both Claude launchers, qualified Cursor product surface
and Grok cross-consumption. Cursor IDE evidence cannot imply Cursor CLI PASS.
The slice cannot complete with a required entry's unknown loading or failed
behavior. If a supported acceptance mechanism is unavailable, return BLOCKED
and revise scope through approval; never silently waive it.

After Implementation Review PASS, apply the existing project learning process,
fresh final verification and independent Final Review. Owner reconciliation
and temporary/raw-trace cleanup occur only when gates permit. Existing four
portable targets/CCG remain byte assertions, not a new sync deployment.
Native rule adaptation completion still does not mean seven-name equivalence,
hook isolation or Superpowers compatibility complete.

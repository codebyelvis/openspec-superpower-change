## One Candidate per File

Claude CCG append and the isolated path clause form one candidate built from
the same preimage. Do not use the original Claude hash for a second patch.
CCG wrapping reuses `install_managed_block`, `replace_managed_block` and
`validate_managed_rule_parity` from the existing sync script; the four-target
apply interface must not be retargeted to these native destinations.

Each candidate manifest row binds the exact native path, regular-file type,
original mode, preimage hash, owned edit, preserved-byte digest and result hash.
Original line numbers aid reading only; apply matches complete exact text.
Account A personal author/authentication/data-source rules, Claude report
isolation and existing Claude/Grok Obsidian overrides remain outside ownership.
No industry-specific overrides are added to default Codex or Cursor.

### Preserved-byte digest definition

The existing candidate manifest digest is computed from the original UTF-8
bytes without newline normalization: remove each unique `exact-text.old` once,
in edit order; if a version-6 managed block remains, use `_marker_parts` to
remove its body only and retain both literal markers and all prefix/suffix
bytes; UTF-8 encode the remainder and bind SHA-256 plus byte length.
This explains the Grok digest: it excludes the three old exact-text spans and
the original managed body although that body is unchanged by the candidate.
The digest alone is not complete unchanged-byte evidence. Grok CCG additionally
requires original/candidate body byte equality and canonical parity. Other
outside bytes retain reversible exact-edit proof; appends preserve the original
prefix. No candidate hash changes to add this definition.

## Actual Entries and Transitive Consumers

The original seven names imply eight configurations: default Codex, account A,
claudex, claudeg, Cursor, Grok, Pi and agy. This slice's affected consumers are
the first six; Pi/agy bytes and portable records remain unchanged assertions.
Default Codex binds both its AGENTS and model instructions, while account A
does not bind the latter. The two Claude launchers use one rule file but require
distinct actual session identities. Cursor IDE and CLI are separate evidence
scopes. Grok may consume Claude and Cursor changes as compatibility inputs.

Before mutation, bind each affected native entry's actual launcher/config root,
native rule discovery, skill/dependency paths and event mechanism. Current
catalog or inspect metadata is discovery evidence, not native body loading.
Unsupported or unobservable loading must remain pending and block any claim
requiring it. Do not inject candidate content through project AGENTS and call
the resulting classifier native global-rule acceptance.

through classification and an applicable publisher with real launcher/session/
revision. Formal attempts keep their exact bound paths and formats.

The existing publisher protects `*-review.md`, including Companion attempts;
its origin prefix also differs from the formal first-line Review contract.
An incompatibility stops publication rather than renaming the attempt or
bypassing a hook. Preserve publisher SHA-256
`3ec6d1fd6945b619368794374b90a87c3c1abdc3c0f2b079fd186b135d9e5522`
and the exact `claudex`/`claudeg` whitelist. Native Grok does not borrow either
launcher. Keep Companion separate and do not rewrite historical evidence.
Retain personal response-prefix rules. Add P4 as a separate negative mechanism:
`亮哥：# Review Result: PASS` is not a permitted formal report first line.
Check the report body independently of surrounding conversational prose;
do not let a native reply prefix enter immutable evidence or delete the
personal prefix rule to manufacture a passing result.

## Preparation, Apply and Recovery

After specific approval, prepare the executable implementation Plan and
bounded private commands/receipts for this change. The proposed backup root is
`/Users/elvis/Library/Caches/native-agent-adaptation/project-native-r2-20261010/`,
mode 0700, with six mode-0600 preimages and separately bound original modes.
It is outside skill discovery. Collision or drift stops preparation; a new
root requires refreshed binding, not adoption of an existing directory.

Before Preflight, supply actual commands, command hashes, native source/event
auditors and isolated failure injections. Recovery must restore the exact
bound preimage/mode or stop without overwriting concurrent drift. Test failed
candidate checks, preimage changes, linked paths, later-write stopping, receipt
freshness, mode restoration and publisher conflict classification. These tests
must use private fixtures, not live native writes or auth copies.

Independent Preflight reviews the complete executable package. With PASS,
process files 01–06 in the candidate manifest order. Bind source and complete
file prestate again before backup and before replacement; verify candidate,
outside bytes, modes and durable receipt afterward. Stop later writes on failure.
No six-file atomic guarantee or automatic cascading rollback is asserted.
Any conflicting replacement inode or content leaves recovery blocked for the
owner rather than overwriting another writer.

Read-only model acceptance may still invoke hook/session side effects; record
the allowed state and qualified command controls before a launch. Do not use
tools-disabled, plan mode or correct answers as a substitute for event auditing
or mutation checks. No publisher call or report publication is authorized by
this slice; coexistence uses pure-function/fixture probes and classified native
responses. Raw events stay private and temporary; durable evidence contains
only sanitized paths/hashes/enums/counts and limitations.

### Evidence phases

`event-mechanism-qualified` labels pre-write readiness evidence: actual entry,
source observation facility, event parser with unknown/tool-event rejection,
qualified command/timeout and bounded hook/session side effects. It must pass
before any target consumed by that entry is changed. A supported command name,
documented event schema or parser fixture alone is partial evidence.

`native-load/behavior-accepted` labels post-write evidence from a fresh real
entry: the candidate body/source loading, scenario classifications and audited
events under the already-qualified mechanism. It remains pending until then.
Old-config diagnostics cannot establish candidate acceptance. These are local
evidence-phase labels, not new canonical states or Handoff schema fields.

The current Codex debug prompt-input checks observed each respective complete
AGENTS body in the native input list without a project projection or model call.
They did not expose the complete default model_instructions body in that list;
this does not prove that body is inactive, and that source mechanism remains
pending. Behavior and the other native entry mechanisms remain pending.

## Verification and Completion

Required offline checks: managed parity, exact-edit reversibility, preserved
bytes/modes, dependency/publisher/excluded-target invariance, failure-injection
recovery and A–F/P1–P4 expectations from the r3 plan. Required native acceptance
covers both Codex roots, both Claude launchers, qualified Cursor product surface
and Grok cross-consumption. Cursor IDE evidence cannot imply Cursor CLI PASS.
The slice cannot complete with a required entry's unknown loading or failed
behavior. If a supported acceptance mechanism is unavailable, return BLOCKED
and revise scope through approval; never silently waive it.

After Implementation Review PASS, apply the existing project learning process,
fresh final verification and independent Final Review. Owner reconciliation
and temporary/raw-trace cleanup occur only when gates permit. Existing four
portable targets/CCG remain byte assertions, not a new sync deployment.
Native rule adaptation completion still does not mean seven-name equivalence,
hook isolation or Superpowers compatibility complete.

Operational factual metadata for the specifically approved draft-v2 scope only.
This does not approve the proposed Codex-first amendment, relax prerequisites,
or constitute actual reviewer signoff. Implement permission remains subject to
qualified mechanisms and independent Preflight in the above contract.

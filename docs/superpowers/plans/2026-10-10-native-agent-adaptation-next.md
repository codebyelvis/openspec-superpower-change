## Background and current state

The two source repositories already own Router governance and Companion
handoff/evidence rules. The existing manifest transaction owns forty portable
files and the four declared managed blocks. Alternate Codex account A discovers
both Skills through the shared native catalog despite their absence from its
private skills directory; that establishes discovery, not native body loading,
behavior or control-plane authority. Claude/Cursor consume shared content;
`claudex` and `claudeg` remain Claude Code launchers, irrespective of backend.

The remaining mismatch is native consumption: account A/Claude lack CCG,
Cursor retains an older governance projection and Superpowers link, native
plan defaults in three files require finishing-time persistence, and Grok's
review-save policy and imported Claude publisher hooks have compatibility
risks. Static conflicts are not proof that all seven entries have failed.

## Research and decision

[Rulesync's official feature matrix](https://rulesync.dyoshikawa.com/reference/supported-tools.html)
contains these product families and scopes. Current Cursor `rules` support is
listed for project mode; do not assume native global-rule generation. Its
[separate input root](https://rulesync.dyoshikawa.com/guide/separate-input-root)
is useful for an isolated candidate-generation trial, but format generation
has not been shown to preserve this project's receipt/recovery or identity
contracts. Pin a version and inspect its code before any such trial.

[Vercel Skills](https://github.com/vercel-labs/skills) is an installation
candidate; [Ruler](https://github.com/intellectronica/ruler) is a rule-distribution
candidate. Neither was selected to replace already-working manifest parity,
managed-body ownership, evidence acceptance or completion authority. No package
installation or generation into real HOME is part of this follow-up MVP.

Maintain one editable authority for each content item, with platform formatting
and discovery as thin projections. Preserve Companion as an independent Skill:
chat advisory, external attempt/hash bindings, retry/recovery and Router return
are workflow responsibilities, independent of distribution tools. Keep both
handoff files as current compatibility snapshots; deduplication is a separate
contract migration. Seven launch entries are not seven formal schema products.

## Implementation proposal by slice

1. Native managed projections: create a separate approved exact-path patch
   package for account A, Claude and Cursor. Reuse the existing managed-block
   render/parity primitives, not a new general installer; use a native-specific
   receipt/check because the four-target plan deliberately rejects these paths.
   The package must bind canonical body hash, every prestate, preserved-byte
   digest, candidate hash and a per-file restore action before any write.
2. Native defaults/dependency: patch only the plan/review clauses listed above.
   Required plans exist before execution; user/project/contract destinations
   govern; `docs/design/` remains fallback. Ordinary standalone advisory stays
   chat; saving it returns to Router and uses an applicable publisher. Governed
   batches retain exact attempt paths and format. Validate Cursor's proposed
   dependency before changing its link; do not upgrade every dependency or copy
   an entire agent persona into another platform.
   Claude's existing `CLAUDE.md` path-conflict clause currently proposes a
   session-specific replacement path. Qualify only that routing clause: offer
   another publisher-compatible destination only for unbound advisory output
   when the user's scope permits it; an immutable binding or incompatible
   authorized path/format must stop publication and report the conflict. Keep
   launcher/session/revision naming, protected filename guards and publisher
   command requirements unchanged. Preserve project-specific Obsidian ownership
   overrides in all native files; a generic plan fallback cannot override them.
3. Grok selective hook isolation: discovery says Claude compatibility hooks are
   registered, not that a real Grok write was blocked. A selective exclusion
   mechanism for only `review_report_guard` has not been verified on installed
   Grok 1.0.50. This slice is **not implementation-ready**: first prove a supported
   filter in an isolated configuration and preserve unrelated codeisland and
   other protections. Do not blanket-disable Claude compatibility hooks. No
   configuration mutation path or permission is requested until the mechanism,
   exact owned keys, prestate and rollback are concrete.

Every slice requires a separate scoped approval and independent readiness/review
under the existing Router. Approval of this plan's delivery grants no native
writes. Do not combine an unverified hook mechanism with already-concrete rule
patches, or grant account A governance authority solely by appending CCG.

actual rule/Skill/dependency discovery paths and hashes. Observe native loading
where the harness exposes it; an answer or correct files alone cannot prove
body loading. Run fresh read-only advisory, compact-local, compact-external,
unapproved Major, bound-plan and invalid identity/evidence cases through the
actual entry with sanitized native events. Missing native proof stays explicitly
pending; never convert a Codex projected-AGENTS result into seven-entry PASS.

Claude launcher publication tests must use each real launcher/session identity
and the approved draft/published paths. A formal batch cannot borrow those
names or a publisher prefix that violates its bound first-line contract. Keep
formal schema assignment at the existing four products; Claude/Cursor remain
advisory consumers unless a separate Major schema extension is approved.

Before each write: recheck file/link type, canonical source hash and prestate;
create a mode-0600 backup outside discovery. Verify owned candidate and unchanged
outside bytes, then native discovery/behavior. On failure restore only the
current file/link from its verified preimage, verify restoration and stop later
writes. Never overwrite concurrent drift. Keep recovery evidence until a
successful independent final review, then remove temporary backups.
